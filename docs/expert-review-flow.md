# 正式专家审阅接入（2026-10-14）

## 本期边界

正式病例从现有可行性/专业报告提交表读取，专家可查看全部病例；不做病例分配。沿用已通过原型的正式报告渲染，不再把报告改排成文本卡片。

用户填写的非身份信息、医学日期、病史、指标、资料全文及附件预览是审阅前提。姓名、联系方式、生日、证件号、具体地址脱敏。原始附件不公开，预览必须经文件级遮盖确认；未完成脱敏的文件明确显示待处理，不用OCR摘要冒充原件。

## 流程与门禁

1. 后台开通实名操作账号（没有自助注册）；专家仅修改自己的审阅。
2. 读取病例的脱敏输入和报告，冻结原始报告版本；分模块保存批改、依据、引用的资料。
3. 服务端验证模块均已确认、原始报告版本未变化，再提交并锁定；重复提交幂等。
4. 明确勾选的医学修改/补充建议形成可复用知识，保留适用条件、不适用条件、证据与原稿位置；病例原文不能直接当成通用规律。普通批注及未勾选内容只保留审阅记录，不当通用医疗规律套用。
5. 按用户最新要求，**当前部署专家提交后直接发布**为 `expert_published`，并供后续新方案检索；草稿不入库。`EXPERT_KNOWLEDGE_REQUIRE_CONFIRMATION=false` 显式开启；新环境默认 `true`，此时新提交为 `pending_confirmation`，且仅专人已确认内容可检索。专人确认操作为后续功能，本期不开放。
6. 生成器按下述混合匹配流程检索当前策略允许的知识，作为非执行性参考传入医疗模型。待确认/撤回/过期/条件不匹配均不进入提示词；历史报告不覆盖，不做模型训练。管理员或原提交专家可撤回，后续检索立即排除（已经开始的生成保留其版本快照与追溯）。

## 智能匹配升级

算法版本 `hybrid-e5-bm25-medical-rerank-v1`：

1. 从脱敏医学字段、病历摘要和高置信度医学事实构造检索资料，不使用姓名、联系方式、文件名或存储路径。
2. 先筛疾病、发布策略、有效期、有效账号和已提交来源；必需/排除条件、疑似/否定、分期、术前术后、指标阳阴性冲突或缺失采用硬拦截。
3. 本地多语言 E5 向量 + 中文 bigram/中英医疗同义词 BM25 + 关键词混合排序。向量缓存绑定知识 ID、版本、模型版本与内容 SHA256；损坏缓存重算。
4. 每模块最多取 5 个候选，使用现有医疗模型核验全部适用/排除条件，要求返回病例中的连续原文证据；缺失、伪造证据、低相关、故障或同模块相反建议均拒绝。不在冲突核验前用向量去重。
5. 核验后按模块去重、排序并分配上下文，每模块最多 3 条/16000 字符、整次检索最多 36000 字符；不再采用整份报告固定 top4，也不为凑数引入低相关知识。每次生成调用仅接收其目标模块的参考。
6. 追溯记录实际提供给模型的知识 ID/版本/模块、检索分、适用证据、发布依据及拒绝原因；召回但未提供的条目不计入引用。提供参考不代表模型已采纳。

相关分和 E5 cosine 都不是临床概率。当前阈值是工程初值，后续需要专家标注的相关/不适用样本校准，并非已验证的临床准确率；适用性模型也可能出错，报告仍需医疗专业人员复核。

向量模型不调用远程 embedding API，运行时禁止下载。适用性核验会将脱敏医学摘要与候选传给**现有医疗模型服务**，增加一次最多 45 秒的核验调用。语义模型故障、候选核验故障、同病种知识超过 2000 条或医学资料超过 20000 字符时，不使用不确定知识兜底，保留原生成流程并记录原因；后两种情况需升级索引/安全压缩能力。

当前使用内存 BM25 与向量扫描，并非已接入 pgvector 索引。模型固定为 `Xenova/multilingual-e5-small` 的 `761b726dd34fb83930e26aab4e9ac3899aa1fa78` revision、q8 ONNX、384 维，配置目录 `EXPERT_EMBEDDING_MODEL_DIR`；`config.json`、`tokenizer.json`、`tokenizer_config.json`、`onnx/model_quantized.onnx` 启动时校验固定 SHA256。模型是通用多语言检索模型，不是专训医疗模型；文件留在服务器/本地缓存，忽略 Git。
